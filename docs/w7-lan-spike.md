# W7 技術驗證：區網連線

目標：iPad 與電腦在**同一個 Wi-Fi** 下直接連線，即時同步同一本筆記本（W9–W11 正式做協作的前提）。
最大的風險是瀏覽器對「https 網頁連區網裝置」的限制，所以先驗證可行的連線方式。

## 結論

**用 WebRTC DataChannel 讓裝置之間直接連線。** 已做出可用的原型（測試版），兩台裝置交換一次「連線碼」後，
筆跡、頁面、標題、原始 PDF 都會同步，資料不經過任何伺服器。

剩下要決定的是「怎麼交換連線碼」（見最後一節）。

## 各種連線方式的限制

網頁版放在 `https://boxcat-none.github.io/Tool/`，iPad 用的是這個網址（或加入主畫面的 App）。

| 方式 | 結果 | 原因 |
|---|---|---|
| 網頁連電腦上的 WebSocket（`ws://192.168.x.x`） | ❌ | https 頁面不能連 `ws://`（混合內容），iPad Safari 直接擋掉；Chrome 147 起連區網位址還要使用者同意「區域網路存取」權限 |
| 電腦用 `https://` + 自簽憑證開 WebSocket | ❌ | iPad 要手動安裝並信任憑證，一般使用者做不到 |
| 電腦開一個 `http://` 網址給 iPad 開 | ⚠️ 可以連，但不適合 | 不是安全環境：沒有離線功能（Service Worker）、沒有 `crypto.subtle`；而且資料存在另一個網址底下，看不到 iPad 原本的筆記本 |
| **WebRTC DataChannel** | ✅ | https 頁面可以用；同一個 Wi-Fi 下直接走區網（用 mDNS 的 `.local` 名稱找到對方，不會洩漏 IP）；連線本身強制加密（DTLS） |
| 雲端中繼（WebSocket 伺服器） | ✅ 但需要伺服器 | 留到 W14（雲端同步） |

各平台的 WebRTC 支援：

| 平台 | 支援 | 備註 |
|---|---|---|
| iPad／iPhone Safari、主畫面 App | ✅ | iOS 15 起預設使用 mDNS 位址；**待實機確認** |
| Windows／Mac 的 Chrome、Edge、Safari | ✅ | |
| 軟體版 Windows（WebView2） | ✅ | WebView2 就是 Chromium；**待實機確認** |
| 軟體版 macOS（WKWebView） | ✅ 應該可以 | 尚未測試 |
| 軟體版 Linux（WebKitGTK） | ❌ | 已確認（Ubuntu 的 WebKitGTK 2.52 沒有 `RTCPeerConnection`）；畫面會提示改用瀏覽器，有自動測試 |

## 原型

| 檔案 | 內容 |
|---|---|
| `packages/notes/src/sync.ts` | 同步協定，和連線方式無關：Yjs 更新（y-protocols sync）、awareness（線上狀態）、檔案庫傳輸（缺的檔案才要，64 KB 分塊，收完驗證 SHA-256） |
| `apps/web/src/sync/webrtc.ts` | WebRTC 連線、連線碼（SDP 壓縮後 base64，約 570 字） |
| `apps/web/src/sync/hub.ts` | 目前連上的裝置（每本筆記本可以連好幾台） |
| `apps/web/src/sync/SyncDialogs.tsx` | 「連線」與「加入其他裝置的筆記本」畫面 |

### 使用方式（測試版）

1. 電腦：開啟筆記本 → 工具列「連線」→「邀請另一台裝置」→ 複製邀請碼，用 LINE、訊息或 Email 傳到 iPad
2. iPad：書櫃 →「加入其他裝置的筆記本（測試版）」→ 貼上邀請碼 →「產生回覆碼」→ 複製，傳回電腦
3. 電腦：貼上回覆碼 →「連線」
4. iPad 收到整本筆記本（含 PDF）後自動開啟；之後兩邊的修改即時同步

- 加入方已經有這本筆記本（之前連過）時，直接開啟並合併雙方離線時的修改，不會變成兩本
- 一台可以同時連好幾台；A 同時連 B、C 時，C 的修改會經過 A 傳到 B
- 離開筆記本就中斷連線；對方會收到「連線已中斷」
- 收到的修改不會進入本機的復原紀錄：在 iPad 按復原，不會復原電腦剛寫的字
- **正在畫、還沒放開的筆畫**也會即時出現在對方畫面（W8）：透過 awareness 每 50 毫秒送一次整筆
  （座標取到 0.1 pt；300 點的長筆畫一次約 5 KB，畫的時候約 100 KB/s），放開後才寫進筆記本，對方的預覽同時清掉
- 「連線」按鈕的提示與連線視窗會顯示**對方正在看第幾頁**，點一下就跳過去（W8）

### 量測（同一台電腦上的兩個瀏覽器，Chromium）

| 項目 | 結果 |
|---|---|
| 配對（交換連線碼後到 B 開好筆記本） | 1.2 秒 |
| 一筆筆跡從 A 放開到 B 顯示 | 約 0.1 秒（含測試程式畫線的時間） |
| 28 MB／300 頁 PDF 傳給新裝置並開啟 | 3.2 秒（8.3 MB/s）；傳送時顯示進度 |
| 同步協定（記憶體通道）20 MB 檔案 | 0.3 秒 |

實際 Wi-Fi 的速度會比較慢（通常 2–10 MB/s），要在 iPad 實機量測。

### 測試

- 單元測試 `packages/notes/test/sync.test.ts`（12 項）：離線各自修改後合併、即時同步、復原只復原自己的、
  新裝置收到整本與原始檔、連線中新增的檔案自動下載、損毀的檔案丟棄、兩邊都沒有的檔案不會一直等、
  20 MB 大檔案、awareness 與斷線清除、Hello 交換（訊息不遺失、版本不同時拒絕、斷線不卡住）
- 瀏覽器 e2e（28 項）：三個獨立的瀏覽器（各自的 IndexedDB，等於三台裝置）實際走 WebRTC，
  涵蓋上面的使用流程、斷線、重新連線合併、PDF 筆記本（中文正常顯示）、同時連兩台、貼錯連線碼的提示

## 已知限制

| 項目 | 說明 |
|---|---|
| 連線碼要手動傳兩次 | 約 570 字，要用 LINE 等方式傳；見下一節 |
| 有些 Wi-Fi 不允許裝置互連 | 公司、學校、飯店常開「用戶端隔離」，或擋 mDNS → 連不上（會提示）。要靠 TURN 中繼或雲端（W14） |
| 不會自動重新連線 | iPad 休眠、切到別的 App、離開筆記本後要重新配對 |
| 同步單位是一本筆記本 | 不會同步整個書櫃 |

## 下一步：怎麼交換連線碼（W9 前要決定）

| 方案 | 優點 | 缺點 |
|---|---|---|
| A. 手動複製貼上（目前） | 不需要任何伺服器、沒網路也能用 | 要傳兩次很長的字串，麻煩 |
| B. QR code | 電腦顯示 QR code，iPad 用相機掃描 | iPad 相機掃到網址會開 Safari，不是主畫面 App（兩邊資料分開）；回覆碼還是要傳回電腦 |
| C. **配對伺服器** | 輸入 6 位數配對碼（或掃 QR code）就連上，最接近 AirDrop 的體驗 | 需要一個很小的伺服器轉送連線碼（只轉送一次、幾 KB，筆記內容仍直接在裝置之間傳）；可以用 Cloudflare Workers 免費方案，需要建立帳號 |

**建議 C**，保留 A 當作沒有網路時的備案。配對碼只用來找到對方並驗證連線碼（防止伺服器竄改），
筆記內容仍然走裝置之間加密的 WebRTC，伺服器看不到。
